# Overview

One of the biggest architectural improvements introduced in Phase 4 was the addition of vector database capabilities.

Traditional relational databases are designed to store structured information such as numbers, text, dates, and relationships. While they excel at transactional workloads, they are not designed to understand the semantic meaning of natural language.

To enable semantic memory retrieval, PostgreSQL was extended using the **pgvector** extension. This allows the database to store vector embeddings generated by a Machine Learning model and perform similarity searches directly inside SQL.

With the completion of **Phase 8**, the vector database has evolved from a semantic memory retrieval engine into a unified vector retrieval layer supporting both **memories and documents**.

The retrieval engine now combines semantic search, keyword search, metadata filtering, query rewriting, cross-encoder reranking, personalization, diversification, and intelligent context selection.

Document chunks are also converted into vector embeddings and stored in PostgreSQL using pgvector, allowing uploaded documents to participate directly in the Retrieval-Augmented Generation (RAG) pipeline.

# Document Vector Schema

Phase 8 introduced vector storage for document chunks.

```text
document_chunks

id

document_id

chunk_index

content

embedding VECTOR(384)

created_at
```

Each uploaded document is divided into smaller semantic chunks, and every chunk receives a 384-dimensional embedding.

This allows the vector database to perform semantic search over individual document sections instead of treating an entire document as a single retrieval unit.

# Similarity Search

Phase 8 extends semantic retrieval into a unified retrieval pipeline for both memories and documents.

The vector database continues to perform semantic similarity search using cosine distance.

For memories, vector results are combined with:

* Keyword search
* Metadata filtering
* Query rewriting
* Cross-encoder reranking
* Personalization
* Diversification
* Context selection

For documents, the system searches the embeddings of individual document chunks and can apply filters such as:

* Document ID
* File type
* Upload date
* Top-K
* Group by document

Duplicate document chunks are also removed from retrieval results.
